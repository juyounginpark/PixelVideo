### 1. 컷별·단계별 캐시

현재 `render.py`는 `source`를 제외한 전체 에피소드 JSON과 공용 Python 파일들을 한 번에 해시한다. 자막 문구나 오디오 설정도 이 해시 안에 있다. 또한 컷 수정 뒤 최종 manifest의 `sourceHash`가 null이므로 현재 `--resume`은 보수적으로 전체를 다시 렌더한다. 지난 제작에서는 안전한 수동 부분 렌더로 해결했지만 반복 제작에 적합한 자동 구조는 아니다.

권장 의존성은 다음과 같다.

| 바뀐 내용 | 다시 실행할 단계 |
|---|---|
| 자막 문구·색·폰트·배치 | 글리프/레이아웃 검사 → 관련 컷 합성 → 최종 인코딩·검수 |
| SFX 종류·시간·BGM | 오디오 스템/믹스 → 영상 스트림 복사 mux → 최종 음량·동기 검수 |
| 한 컷의 카메라·행동 | 그 컷 3D+앵커 → 해당 합성 → 인코딩·경계 검수 |
| 공용 모델·조명·재질·네이티브 렌더 코드 | 영향받는 모든 컷. 범위를 증명하지 못하면 전체 |
| 컷 길이·프레임 배치 | 변경 컷과 절대 시간/누적 상태가 달라진 후속 컷, 오디오 |

컷별 카메라 수치와 행동 파라미터를 명시적 데이터로 옮기고 공용 코드 버전과 함께 키를 만든다. 문자열 몇 줄의 변경만 보고 임의로 다른 컷을 재사용하는 방식은 피한다. 현재 씬에는 절대 프레임 기반 진동·눈 깜박임이 있으므로 컷 시작 프레임과 시간 의존성도 키에 필요하다.

manifest에는 컷별 소스 해시, 에셋/폰트 버전, 실제 산출물 해시, 검수 버전을 남긴다. 중단 복구를 위해 임시 파일→원자적 교체를 사용하고, 렌더 완료 상태와 시각 검토 완료 상태를 구분한다. 기존 `camrecords={}`가 재개 시 이전 카메라 기록을 버리는 부분도 함께 수정해야 한다.

102/1,050이라는 사례에서는 네이티브 재작업 프레임 수를 약 90.3% 줄였다. **이 효과는 수정 구간에 대한 것이다.** 첫 전체 렌더의 프레임당 처리 속도를 10배 높였다는 의미는 아니다.

### 2. 사전검사

각 컷의 첫/마지막 프레임과 행동·카메라 극값에서 인물 전체·얼굴·과학 주 대상의 투영 경계를 확인한다. 현재 검사는 주로 자막과 얼굴의 겹침을 다루므로 자연스럽게 카메라 밖으로 나가는 인물을 놓칠 수 있다. 의도한 크롭과 오류 크롭은 콘티에 구분한다.

서체별 실제 사용하는 글자의 cmap을 확인하고, 최종 서체·기호 폴백으로 자막 시안을 만든다. 정지 검사 후에는 기존 5초 발견 샘플과 실제 완성 영상의 시간 순서 검토를 유지한다. 사전검사는 애니메이션·편집 품질 검수를 대체하지 않는다.

### 3. 토큰 절감

현재 제작 Python은 프레임별로 LLM을 호출하지 않는다. 우선 줄여야 할 것은 작업을 진행하는 대화에서의 반복 읽기·출력·판단이다. 제 이전 작업 방식의 긴 코드/JSON 출력, 잦은 진행 로그 확인, 수정 범위보다 넓은 이미지 재확인도 개선 대상이다.

- `PROMPT_LOG.md`의 약 126KB 원문 이력은 그대로 보존하고 필요한 U/P 번호만 검색한다. 최신 결정·현재 단계·남은 문제·근거 경로를 짧은 상태 파일로 관리한다. 문서 크기는 토큰 사용량과 같지 않다.
- 1,050개 프레임 번호나 10MB 앵커를 도구 응답으로 출력하지 않고 `완료/전체, 변경 컷, 오류, 산출물 경로`만 반환한다. 상세 자료는 파일로 보존한다.
- 의존 관계가 있는 렌더→합성→기술 QA는 하나의 실행기가 처리하고 모델은 오류·시각 검토·의사결정에 집중한다. 실행기는 중간에 품질 검토가 필요한 지점에서 멈출 수 있어야 한다.
- 최초 전체 레퍼런스 분석은 유지한다. 같은 원본 해시와 같은 프레임은 관찰 기록을 재사용하고, 수정 후에는 변경 컷·인접 전환·최종 대표 화면을 우선 확인한다. 새 레퍼런스나 광범위한 스타일 변경은 재검토한다.
- 기계적으로 판정할 수 있는 디코드·폰트 누락·해시·레이아웃은 코드가 처리하고, 재미·인과관계·감정·가독성 판단은 시각 검토로 남긴다.

향후 별도의 LLM API 제작기를 만들 경우, 안정된 공통 지시와 바뀌는 컷 자료를 분리해 프롬프트 캐시를 설계하고 실제 usage로 확인할 수 있다. 캐싱은 재사용 계산과 비용을 줄이는 수단이며 입력 정보 자체를 삭제하거나 컨텍스트 길이를 줄이는 것과 다르다. 현재 Codex 환경에서 캐시 옵션을 직접 제어할 수 있다고 가정하지 않는다. [OpenAI 공식 프롬프트 캐싱 문서](https://developers.openai.com/api/docs/guides/prompt-caching).

### 4. 앵커·합성·오디오

`native.projected()`는 모든 메시 면의 화면 좌표까지 계산·저장하지만 현재 V3.1 합성기는 point/rect만 사용한다. 폴리곤 마스크가 필요한 효과에서만 면 좌표를 만들고, 나머지는 동일한 정확도의 경계/중심만 제공한다. 공용 V3 마스크 기능을 삭제하면 안 된다. 같은 프레임에서 같은 오브젝트를 surface/molecule 이름으로 중복 투영하는 경우도 결과를 재사용할 수 있다.

현재 15프레임마다 커져 가는 전체 JSON을 다시 쓴다. 컷별 파일·증분 기록·작은 완료 manifest로 분리하면 쓰기량을 줄일 수 있다. 원자적 저장과 중단 복구는 유지한다.

Pillow 프로파일에서는 색 모드 변환, 글자 래스터화, 전체 화면 RGBA 합성이 비용을 차지한다. 고정 크기·스타일 자막은 내용/폰트/크기/색/외곽선 키로 투명 레이어를 캐시하고 등장 위치·알파만 바꾼다. 확대 애니메이션은 검증된 크기별로 캐시하거나 원래 방식으로 렌더해 한글 선명도를 유지한다. 캐시 전후 합성 픽셀을 비교해야 한다.

글자 수정 때도 현재는 오디오를 다시 믹스·정규화한다. 길이·음원 해시·SFX 이벤트·gain·duck·샘플레이트·정규화 버전이 같으면 음원 결과와 측정 기록을 재사용한다. 최종 mux의 AAC 피크·동기 검수는 남긴다.

### 5. 추가 후보와 보류 이유

- **Intel QSV:** 설치된 FFmpeg에 `h264_qsv`가 등록되어 있다. 실제 장치 초기화 성공이나 속도·품질은 아직 시험하지 않았다. 고정된 같은 프레임으로 x264 fast와 QSV를 비교하고, 한글 외곽선·픽셀 경계·밴딩·파일 크기를 함께 평가한다. 인코딩 가속으로 Blender 렌더까지 빨라진다고 계산하지 않는다. [FFmpeg QSV 문서](https://ffmpeg.org/ffmpeg-codecs.html#QSV-Encoders).
- **로컬 임시 캐시:** OneDrive 밖의 로컬 임시 디렉터리와 현재 경로의 I/O를 비교한 후 채택한다. 공급 자료·최종 영상의 보존 위치는 유지할 수 있다. 현재 OneDrive가 실제 병목이라고 확정하지 않는다.
- **씬 처리:** `view_layer.update()`가 pose와 호출부에서 반복되고, 숨김 상태를 반복 설정한다. pose/투영/렌더/PNG 저장을 따로 계측한 다음 중복 업데이트·정적 메시·인스턴싱을 개선한다. 지금 로그만으로 13분을 GPU 비용으로 전부 귀속하지 않는다.
- **품질 설정:** 이미 540×960·EEVEE 8샘플이다. 30fps 감소, 무작정 해상도/샘플 하향, 검수 생략은 우선안에서 제외한다. 꼭 필요한 경우 별도 A/B 시각·시간 검증 후 채택한다.
- **병렬 렌더/장비 구매/엔진 전환:** 현재 장치에서 이득을 확인하지 못했다. 먼저 소프트웨어 재작업 비용을 줄이고 측정한다.

## 적용 순서와 완료 기준

1. 단계별 시간 계측과 작은 상태 보고를 추가한다. 토큰 usage는 제공되는 경우에만 입력/출력/추론/캐시를 구분해 기록한다.
2. 컷별·단계별 캐시와 글리프/크롭 사전검사를 구현한다. 자막 수정은 네이티브 재렌더 0장, 102프레임 카메라 수정은 해당 102장과 필요한 경계 검증만 수행하도록 테스트한다.
3. 앵커를 축소하고 자막·오디오 결과를 재사용한다. 변경하지 않은 컷은 픽셀/산출물 해시가 같고, 카메라·검수 기록이 복구 후에도 남아야 한다.
4. 같은 버전의 대표 장면에서 QSV·I/O·씬 개선 후보를 각각 측정한다. 첫 제작 시간과 수정 시간, 화질 결과를 따로 보고한다.

실측 없이 ‘토큰 50% 절약’ 또는 ‘전체 렌더 3배 가속’ 같은 목표를 달성값으로 제시하지 않는다. 기존 공급원·중복 방지 기준·최종 1080×1920·30fps·독립 한글 UI·실제 프레임 검수는 유지한다.

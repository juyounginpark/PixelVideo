# 가상 펫 기기 UI — 독립 비평과 확정 제작 구조

2026-10-12 / U-069. 사용자 요청에 따라 비평 에이전트 1명 운영.

## 검토 근거와 한계

비평가는 실제 8개 시안 화면과 합성 코드를 검토했다. 전체 동영상의 움직임이나 시청 유지율은 평가하지 않았다. 아래 수치는 레이아웃 값이며 성과 보장이 아니다.

## 비평

“다마고치 외형은 전달되지만 릴스 내용이 작은 화면에 갇힌 느낌이 강하다.”

1. 부팅과 각색 표시의 깨진 한글은 배포를 막아야 하는 결함이다.
2. 1.5초 로딩 화면은 첫 3초의 절반을 사건 정보 없이 소비한다.
3. 내부 화면이 전체 면적의 56.25%에 불과하다. 기기 장식이 영상보다 공간을 많이 차지한다.
4. 자막을 영상과 함께 줄여 32px가 24px가 된다. 모바일에서 읽기 어렵다.
5. 제목 소제목과 상단 브랜드가 중복된다. 실제 사진 위 여백과 작은 출처도 개선해야 한다.

## 이번 반영

- 내부 화면: 612×1088, 좌표 (54,104). 전체 면적의 72.25%.
- 별도 로딩 대기 삭제. 사건 화면 위 0.4초 점등선으로 기기 켜짐 표현.
- 자막은 최종 720×1280에서 32px로 따로 합성. 행간 42px. 최종 샘플에서 줄바꿈 점검.
- 제목 소제목 삭제. 제목·서사·각색·자료 출처만 남김.
- 자료 사진 확대, 짧은 출처는 최종 약22px. 전체 출처는 기존 대본 문서에 보존.
- 버튼과 테두리는 고정. 무음. 수정 헤어 모델과 실제 카툰 셰이더 사용.

## 공통 제작 지침

1. 영상 영역은 전체 면적 70% 이상. 프레임이 내용보다 먼저 읽히면 실패다.
2. 첫 화면부터 이상한 사건을 보여준다. 기기 부팅을 기다리게 하지 않는다.
3. 자막은 32~36px, 최대 두 줄을 기본으로 한다. 길면 문장을 나누며 폰트를 줄이지 않는다.
4. 제작 방식, 대화 이력, 사용자 피드백, 품질 자랑, 의미 없는 상태 메시지는 UI에 넣지 않는다.
5. 제목·내용 자막·시간 변화·각색/실제 자료 구분·짧은 출처만 허용한다.
6. 픽셀 효과는 캐릭터·장면·기기 그래픽에 적용한다. 글자와 실제 자료의 판독성을 지킨다.
7. 귀여움은 색과 형태로, 미스터리는 사건과 행동으로 표현한다. 의미 없는 하트·스티커·깜박임 금지.
8. 첫 3초, 긴 자막, 얼굴, 버튼 동작, 실제 자료를 최종 출력 크기로 검토한다.
9. 정지 화면 평가는 애니메이션 품질 검증을 대신하지 않는다. 성과는 실제 게시 후 별도로 측정한다.

## 최종 구조

사건 + 기기 점등(0~0.4초) → 후킹 → 제목 → 민수의 체험 → 실제 사진과 설명 → 첫 사건 화면 복귀. 총46초, 무음.

## 2차·3차 재검토 결과

2차에서는 화면 확대 후 남아 있던 기존 껍질의 곡면과 구버튼 그래픽이 충돌한다는 지적을 받았다. 옛 외곽과 하단 요소를 제거하고 화면 치수에 맞춰 기기를 다시 그렸다.

3차에서 비평 에이전트가 최신 시안을 다시 열어 확인했다: “프레임 돌출과 구버튼·하단 그래픽 중첩은 해결됐으며, UI 구조는 잠정 통과다.” 이 판정은 정지 화면 UI 구조에 한정한다. 모델링·표정·카메라 연출의 승인으로 취급하지 않는다.

미해결/별도 검수: 첫 후킹 구도에서 인물이 빈자리를 가리는 문제, 각색/쪽지 재현 배지의 정보 중복, 실제 휴대폰에서의 앱 UI 가림, 체감 자막 노출 시간. 배지 중복은 다음 합성 개정에서 단일 배지로 통합한다.

파일 검증: 46초, 720×1280, 24fps, 1,104프레임, 오디오 없음. 전체 디코드 통과. 0.5초 간격 자막 검사에서 2줄 초과 없음. 이 검사는 실제 시청 가독성 검증을 대신하지 않는다.
